# Perrier kernel patch series

The patches are generated by `../export_patches.py` from the canonical files
under `../source/`, against the recorded Linux 6.18.48 archive. Edit those
source files rather than editing generated patches. `manifest.json` records
the base archive, patch hashes and before/after source hashes; `series` gives
the application order.

| Patch | Purpose |
| --- | --- |
| `0001-dt-bindings-cyttsp4-perrier.patch` | Document Perrier's older Cypress Gen4 profile using ordinary supply, GPIO, IRQ and touchscreen properties |
| `0002-input-restore-cyttsp4-dt.patch` | Restore the last upstream CYTTSP4 core and adapt it to current APIs, DT and the captured older controller protocol |
| `0003-drm-omap-pll-search.patch` | Generic inclusive upper-bound correction in the PLL multiplier search |
| `0004-drm-omap-dsi-host.patch` | Generic DSI line-clock arithmetic, VC completion, NULL transfer, bridge lifecycle and shutdown handling |
| `0005-drm-bridge-tc358765.patch` | TC358765 support in the existing Toshiba bridge driver, including checked regmap transport and the measured Perrier profile |
| `0007-arm-dts-cisco-perrier.patch` | Add consolidated board wiring, separate RAM policy and the normal ARM DT Makefile target |
| `ram-only/0001-perrier-ram-safety.patch` | Preserve inherited clock/PMIC policy and force eMMC read-only during development |

The input driver retains upstream startup, mode switching, recovery and
controller-watchdog structure. It uses GPIO descriptors, ordered regulator
supplies, a threaded IRQ, standard touchscreen transforms and native input
slots. The I2C adapter reserves both measured addresses and launches the
existing touch application; it has no controller firmware update path.

The panel and backlight use existing `panel-lvds`, fixed regulator,
`pwm-backlight`, OMAP timer PWM and GPIO drivers. Their verified GPIOs,
polarities, delays and pad mux values live in DT. No Qt coordinate/scanout
compensation or direct userspace power-register writes are part of this
image.

DISPC and DSS are pristine mainline, qualified together in ram91 after
independent ALIGN and core-clock controls. Mainline porch and pad-mode
allocation also passed. The PLL search floor is removed; the inclusive
multiplier bound fix stays in its own generic patch. The exporter omits
empty groups, so there is no `0006-drm-omap-perrier-sync.patch` while those
source overrides are absent. See
[`display-reduction.md`](../display-reduction.md).

The qualified display pipeline uses mainline HSYNC and video setup,
generic PHY pre-enable/post-disable phases, and a bridge-requested HS NULL
after physical reset release. It replaces the old VC0 L4 dependency with
ordinary video-channel setup. A small `dsi.h` change makes completion
callbacks track the requested virtual channel. Common-DCO arithmetic fixes
line totals without a board-name check; regmap handles bridge I2C with
explicit endianness and error propagation. Ram93 removes temporary timing
instrumentation and tests leaving the stopped video VC disabled; late
control transfers use VC_CMD. Qualification is recorded separately in
`validation-ramNN.json`. Ram70 remains the preserved fallback.

## Work before an upstream submission

The host patch contains reusable OMAP changes. The bridge patch retains a
machine-compatible check and measured panel/PHY programming for Perrier;
these values are not established defaults for other TC358765 boards.
An upstream submission still needs review of that hardware description,
finer commit separation where appropriate and testing on other users.

The board now reuses the upstream OMAP4460 interconnect, target modules
and controller nodes. Board wiring and RAM policy are separate. See the
[bus migration record](../bus-migration.md). The RAM DT disables unused
branches and retains the earlier power policy while preserving GPIO latches
and watchdog/system-timer ownership. Production runtime power domains,
rail power-down, suspend/resume, PMIC integration and SMP remain follow-ups.

The RAM-only patch is a development safeguard, not a general upstream
behavior change. A future production image needs its own reviewed storage,
clock and power policy.
