# Room Navigator CE26.5: symlink-following ownership change

Date: 2026-11-07. Scope: offline analysis of the downloaded CE26.5 image and disposable `/tmp` probes. No Room Navigator device was changed or tested.

## Finding

The `swupgrade` user can write `/config/extensions` (`2775 root:swupgrade` in `firmware/room-navigator-ce26.5/rootfs-unpacked/etc/tmpfiles.d/main.conf:10`). If it places `extensions.json` as a symlink to the existing `/run/sysconfig.d` directory, the root-privileged `ExecStartPre=+` command in `lib/systemd/system/peripheral-swsync.service:9-16` changes the **target directory's** owner to `swupgrade`. The target is normally `2775 root:config` (`etc/tmpfiles.d/basic.conf:52`), and `swupgrade` is not a member of the `config` group (`etc/group:22,30`). Changing ownership therefore crosses a real Unix permission boundary. The `+` prefix exempts this pre-start command from the unit's `User=swupgrade`/`Group=swupgrade` restrictions ([systemd.service](https://www.freedesktop.org/software/systemd/man/249/systemd.service.html)).

A concrete root execution path follows from the newly writable directory:

1. A `swupgrade`-controlled process creates a Bash startup file under `/config/extensions` and arranges for `/config/extensions/extensions.json` to point at `/run/sysconfig.d` before `peripheral-swsync.service` next starts. That service requires `/run/sysconfig.d/use-swsync` and `/run/tam_success` (`peripheral-swsync.service:5-6`).
2. The service's privileged pre-start checks `test -e` and runs `/bin/chown swupgrade /config/extensions/extensions.json` (`peripheral-swsync.service:15`). Both follow this symlink to the directory. The service uses `Restart=always` (`:12`), but a start or restart after placement remains a necessary precondition.
3. Once `/run/sysconfig.d` belongs to `swupgrade`, that user can create or replace an `ssh` file there (the directory is not sticky). An `EnvironmentFile` assignment `BASH_ENV=/config/extensions/<controlled-file>` is then supplied to the root `sshd.service` (`lib/systemd/system/sshd.service:5-9`).
4. The packaged `fswatcher` monitors `/run/sysconfig.d` (`etc/fswatcher.conf:4`) and has a static `ssh=systemctl restart sshd.service` mapping (`etc/sysconfig.services.d/sysconfig.ssh:1`). Its inotify path dispatches on `IN_CLOSE_WRITE` or `IN_MOVED_TO` without checking the modified file's owner or contents; see decompilation findings below.
5. On restart, the first `sshd.service` pre-start command is `/bin/sshd_generate_kex_config` (`sshd.service:7`), whose first line is `#!/bin/bash` (`bin/sshd_generate_kex_config:1`). systemd supplies `EnvironmentFile=` variables to spawned service processes ([systemd.exec](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html)). Noninteractive Bash reads and executes `BASH_ENV` before its script ([Bash manual](https://www.gnu.org/software/bash/manual/html_node/Bash-Startup-Files)). This pre-start runs as root, before `/bin/genericwrapper RUN_SSH On` or the separate `/bin/sshd_keygen` verifier can gate anything (`sshd.service:7-9`).

The payload is interpreted Bash text; `/config` being mounted `noexec` (`etc/fstab:1`) does not stop Bash from reading it as a startup file. This is a device-local `swupgrade`-to-root escalation path, subject to the runtime prerequisites and verification limits below.

## Offline checks

* **Packaged `chown` dereferences the link.** `/bin/chown` resolves to the BusyBox applet. In a disposable `/tmp` directory, the package's AArch64 BusyBox under `qemu-aarch64 -strace -L firmware/room-navigator-ce26.5/rootfs-unpacked` returned success for `chown 1000 extensions.json` where `extensions.json` was a symlink to a directory. The relevant syscall was `fchownat(AT_FDCWD, "/tmp/roomnav-chown.3CXdjh/extensions.json", 1000, 1000, 0) = 0`. The final flags value `0`, rather than `AT_SYMLINK_NOFOLLOW`, means the target was changed. BusyBox's help also describes `-h` as the option to affect the link instead of its target.
* **Watcher dispatch.** IDA decompilation of the packaged `/bin/fswatcher` found `inotify_add_watch(..., 0x88)` in `main` at `0x81c0`, corresponding to `IN_CLOSE_WRITE | IN_MOVED_TO`. The event's filename is passed to `actiondb_register_modified` at `0x9500`; that function compares it with configured action names and marks matching actions pending. `actiondb_foreach_modified` at `0x95c0` calls `run_action` at `0x9100`; `run_command` at `0x235b0` parses the predefined action, and `run_command_args` at `0x234c0` invokes it with `fork`/`execvp`. No file ownership or content validation appears in this dispatch path. The mapping command is fixed by the read-only `/etc/sysconfig.services.d/sysconfig.ssh`, so this is an automatic restart trigger, not command text taken from the changed `ssh` file.
* **Bash startup behavior.** A harmless host `/tmp` reproduction ran a script with a `#!/bin/bash` shebang and `BASH_ENV` pointing at a second file. It printed `BASH_ENV_RAN` before `SCRIPT_RAN`. The firmware's Bash executable was not usable for an equivalent QEMU test: even a simple `bash -c 'printf ...'` exited internally with `bash: xmalloc: shell.c:1551: cannot allocate 56 bytes (0 bytes allocated)`. This is a QEMU/firmware runtime limitation, not evidence that `BASH_ENV` is ignored on the device.
* **SELinux.** The image specifies `SELINUX=enforcing` (`etc/selinux/config:1-2`); file contexts assign `/run/sysconfig.d` to `sysconfig_t` and `/config/extensions` to `extension_files_t` (`etc/selinux/cisco/contexts/files/file_contexts:1231,2031`). Queries against the packaged `etc/selinux/cisco/policy/policy.33` with SETools 4.7.0 show `swupgrade_t` and `peripheral_swsync_t` in the permissive-types list. `sesearch --type_trans -s init_t -t bin_t -c process` and the same query for `shell_exec_t` both return `initrc_t`, which `seinfo -a unconfined_domain_type -x` lists as unconfined. Thus the packaged policy does not appear to block the directory write or the root Bash read. This is a policy-level conclusion; actual runtime labels and domains were not observed.

## Preconditions and limits

* The `extensions.json` symlink must exist before a start of `peripheral-swsync.service`; its two unit conditions must pass. `Restart=always` alone does not prove when the next restart will occur.
* `/run/sysconfig.d` must exist when the symlink is checked; the packaged tmpfiles rule creates it. The watcher must be running when `ssh` is created or replaced. The package lists `fswatcher.service`, `peripheral-swsync.service`, and `sshd.service` in `lib/systemd/system/multi-user.target.wants`, but no runtime state was inspected.
* The firmware image is static evidence. No live Room Navigator was available to verify the complete sequence, the effective runtime SELinux labels, or whether another service promptly restores ownership. The QEMU BusyBox syscall and host Bash test establish the relevant component behavior separately; they are not a full end-to-end device proof.

The affected behavior is the integration of a privileged, symlink-following `chown` with a directory writable by the lower-privilege service. It is not a memory corruption defect in BusyBox, Bash, or `fswatcher`.
